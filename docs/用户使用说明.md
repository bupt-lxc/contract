## 1. 系统概述

### 1.1 系统简介

PO Management Platform（以下简称 POMP）是部门内部用于管理 **SC（采购申请）**、**PO（采购订单）**、**GR（收货确认）** 及 **供应商信息** 的桌面应用。

**核心业务规则**: SC 是预算的根本来源 → PO 将 SC 的预算分配给具体供应商 → GR 从 PO 中核销预算、确认收货。三者形成一条完整的资金链路，任何一环的金额都不能超过上一环的可用余额。

所有业务数据存储在部门的共享文件夹中，各客户端通过网络共享访问同一数据库，无需额外部署服务器。

### 1.2 角色说明

系统提供两种用户角色：

| 角色 | 权限概述 |
|------|----------|
| **管理员 (Admin)** | 拥有全部权限：可管理用户、配置系统通知、查看所有 SC、执行确认/审批/驳回/关闭等管理操作、查看审计日志 |
| **申请人 (Requester)** | 日常业务权限：可创建和管理自己的 SC/PO/GR、提交 SC/PO/GR、撤销自己的 SC、管理供应商 |

**SC 可见性规则**:

- 管理员可看到所有非草稿状态的 SC
- 申请人只能看到自己创建的 SC（包括自己的草稿）以及所有非草稿状态的 SC
- 草稿 SC 仅对创建者本人可见

## 2. 快速入门

### 2.1 启动与登录

1. 双击桌面上的 **POMP** 图标启动应用
2. 系统将自动识别您的 Windows 登录账号，无需手动输入用户名和密码
3. 首次使用时，系统会自动为您创建账号（默认角色为 Requester，如需 Admin 权限请联系管理员）

### 2.2 界面概览

启动后您将看到以下界面结构：

```
┌─────────────┬──────────────────────────────────────┐
│             │                                      │
│  侧边导航栏  │            主内容区域                  │
│             │                                      │
│  · 工作台   │   显示当前模块的列表 / 详情 / 表单       │
│  · SC      │                                      │
│  · PO      │                                      │
│  · GR      │                                      │
│  · 供应商   │                                      │
│  · 邮件     │                                      │
│  · 系统*    │                                      │
│             │                                      │
└─────────────┴──────────────────────────────────────┘
```

- **侧边导航栏**: 点击可切换各功能模块。底部箭头可收起/展开导航栏
- **工作台**: 登录后的首页，展示待办事项和关键数据概览
- **系统** (带 * 号): 仅管理员可见

### 2.3 通用操作

以下操作在 SC、PO、GR、供应商等各列表页中一致可用：

**搜索与筛选**: 每个列表页顶部均有搜索框和筛选面板。

- **文本搜索**: 在搜索框中输入关键词，系统自动在名称、编号等字段中匹配（输入后 0.5 秒自动搜索）
- **高级筛选**: 点击搜索框旁的筛选按钮展开筛选面板，可按状态、日期范围、金额范围等条件组合筛选
  - 日期字段：使用 `从` / `至` 范围选择器
  - 金额字段：使用 `最小` / `最大` 范围输入框

**排序**: 点击列表表头可按该列排序，再次点击切换升序/降序

**分页**: 列表底部显示分页控件，可切换每页显示条数（默认 20 条，最多 500 条）

## 3. SC 管理

SC（Shopping Cart）是整个资金链路的起点，代表一笔采购申请的预算。本章涵盖 SC 的完整生命周期。

### 3.1 SC 列表页

点击侧边栏 **SC** 进入列表页。列表展示所有您有权查看的 SC，包含以下关键列：

| 列名 | 说明 |
|------|------|
| SC 编号 | 系统自动生成的唯一编号 |
| 名称 | SC 的名称/标题 |
| 申请人 | 创建该 SC 的用户 |
| 金额 | SC 的总预算金额 |
| 已用金额 | 已通过 PO 和 GR 分配/核销的金额 |
| 可用余额 | 剩余可用的预算金额 |
| 状态 | 当前所处状态（草稿/经理确认中/待审批/已通过/已驳回/已关闭） |
| 创建日期 | SC 的创建日期 |

点击任意一行可进入该 SC 的详情页。

### 3.2 创建 SC 草稿

草稿功能允许您先保存部分信息，后续完善后再提交。

1. 在 SC 列表页，点击 **新建 SC** 按钮
2. 在弹出的表单中填写基本信息（此时仅需填写申请人，其他信息可后续补充）
3. 点击 **保存草稿** 完成创建

> **提示**: 保存为草稿后，只有您自己可以看到这条 SC。草稿状态下的 SC 不会触发任何审批流程。

### 3.3 SC 状态流转概览

SC 从创建到完成经历以下阶段：

| 状态 | 英文标识 | 说明 | 谁可以操作 |
|------|----------|------|------------|
| 草稿 | draft | 新建后的初始状态，仅创建者可见 | 申请人 / 管理员 |
| 经理确认中 | manager_confirm | 申请人提交后，等待管理员确认 | 管理员 |
| 待审批 | pending | 管理员确认后，进入正式审批队列 | 管理员 |
| 已通过 | approved | 审批通过，可创建 PO | — |
| 已驳回 | denied | 审批驳回，申请人可修改后重新提交 | 申请人 |
| 已关闭 | closed | 业务完结，不再允许操作 | — |

### 3.4 提交 SC

当草稿信息完善后，可将其提交进入审批流程。驳回状态的 SC 也可修改后重新提交。

1. 进入 SC 详情页，确认所有信息已填写完整
2. 点击 **提交** 按钮
3. 系统将对必填字段进行完整校验：
   - SC 名称不能为空
   - 金额必须大于 0
   - 必须关联至少一个供应商
4. 校验通过后，SC 状态将从 **草稿**（或 **已驳回**）变更为 **经理确认中**

> **注意**: 提交后 SC 将变为不可编辑状态（除非后续被撤销），请仔细核对信息后再提交。

### 3.5 管理员确认（经理确认）

SC 提交后首先进入 **经理确认中** 状态，需要管理员确认后才能进入正式审批队列。

1. 管理员进入处于"经理确认中"状态的 SC 详情页
2. 点击 **确认** 按钮
3. SC 状态变更为 **待审批**，正式进入审批队列

### 3.6 SC 审批

**通过审批**:
1. 管理员进入待审批 SC 的详情页
2. 点击 **通过** 按钮
3. SC 状态变更为 **已通过**，此时可对该 SC 创建 PO

> **级联提交**: 审批通过时，系统可自动将该 SC 下所有草稿 PO 一并提交（状态变为 activing）。

**驳回**:
1. 管理员进入待审批 SC 的详情页
2. 点击 **驳回** 按钮
3. SC 状态变更为 **已驳回**，申请人可修改后重新提交（再次提交将回到经理确认中）

### 3.7 关闭 SC

当 SC 下的所有业务均已完结，管理员可将其关闭。

1. 管理员进入已通过 SC 的详情页
2. 点击 **关闭** 按钮
3. 系统校验关闭条件：
   - 该 SC 下所有 PO 必须为 **已完成 (finished)** 状态
   - 该 SC 下所有 GR 必须为 **已通过 (approved)** 或 **已取消 (cancelled)** 状态
4. 条件满足后，SC 状态变更为 **已关闭**

> 关闭后的 SC 不可再创建新 PO，也不可再对现有 PO/GR 做任何变更。

### 3.8 撤销 SC（回退操作）

系统中各状态的 SC 可以通过撤销操作回退到上一个阶段：

| 当前状态 | 撤销后状态 | 谁可以操作 |
|----------|------------|------------|
| 经理确认中 | 草稿 | SC 所有人 / 管理员 |
| 待审批 | 经理确认中 | SC 所有人 / 管理员 |
| 已通过 | 待审批 | 仅管理员 |
| 已关闭 | 已通过 | 仅管理员 |

撤销操作允许在发现错误时回退流程，避免流程僵化。

### 3.9 SC 详情页

点击 SC 列表中的任意一行进入详情页。详情页包含以下信息区域：

- **基本信息**: 编号、名称、金额、状态、创建时间等
- **预算状况**: 总预算、已分配金额、可用余额（实时计算）
- **关联 PO 列表**: 该 SC 下所有的 PO，点击可跳转至 PO 详情
- **关联 GR 列表**: 该 SC 下所有的 GR，点击可跳转至 GR 详情
- **关联供应商**: 与该 SC 关联的供应商列表

### 3.10 SC 供应商关联

在 SC 详情页的供应商区域，可以管理该 SC 关联的供应商：

1. 点击 **添加供应商** 按钮
2. 从供应商列表中选择一个或多个供应商
3. 确认后，选中的供应商将关联到该 SC

- 如需移除关联，点击供应商旁的 **移除** 按钮即可
- 提交 SC 时必须至少关联一个供应商

### 3.11 SC 附件管理

您可以为 SC 上传附件（如合同文件、审批单据等）。

- **上传附件**: 在 SC 详情页点击 **上传附件**，选择文件后确认（支持多文件同时上传）
- **查看附件**: 点击附件名称直接在系统中打开
- **删除附件**: 点击附件旁的删除按钮

附件存储在共享文件夹中，所有有权限查看该 SC 的用户均可访问。

### 3.12 SC 转让

如需将 SC 的所有权转移给其他用户：

1. 在 SC 详情页点击 **转让** 按钮
2. 选择目标用户（仅可选择状态为"启用"的用户）
3. 确认转让

转让后，目标用户将成为该 SC 的新申请人，拥有该 SC 的全部操作权限。

### 3.13 SC 通知设置

每个 SC 可以单独配置邮件通知策略：

1. 在 SC 详情页找到 **通知设置** 区域
2. 可配置以下选项：
   - **启用通知**: 开启/关闭该 SC 的邮件通知
   - **自定义 CC**: 添加额外的抄送收件人
   - **阈值提醒**: 选择需要提醒的预算阈值和时间阈值

## 4. PO 管理

PO（Purchase Order）是 SC 下的采购订单，将 SC 的预算分配给具体供应商。

### 4.1 PO 列表页

点击侧边栏 **PO** 进入列表页，展示所有 PO 的整体视图（跨 SC）。列表包含：

| 列名 | 说明 |
|------|------|
| PO 编号 | 系统自动生成的唯一编号 |
| 所属 SC | 该 PO 对应的 SC 编号 |
| 供应商 | 该 PO 的供应商名称 |
| 金额 | PO 的订单金额 |
| 已用金额 | 已通过 GR 核销的金额 |
| 可用余额 | PO 剩余可核销金额 |
| 状态 | 当前状态（草稿/激活中/已完成） |
| 创建日期 | 创建日期 |

### 4.2 创建 PO

1. **方式一**: 在 SC 详情页，点击 **新建 PO** 按钮
2. **方式二**: 在 PO 列表页，点击 **新建 PO** 按钮，然后选择目标 SC
3. 在 PO 表单中填写以下信息：
   - **供应商**: 从已关联 SC 的供应商中选择
   - **金额**: PO 的订单金额（不能超过 SC 可用余额）
   - **其他业务字段**: 如合同号、备注等
4. 点击 **保存** 创建 PO

> **注意**: PO 的初始状态取决于所属 SC 的状态：
> - 若 SC 为草稿 → PO 创建为 **草稿**
> - 若 SC 为已通过 → PO 创建为 **激活中 (activing)**，可直接开始创建 GR

### 4.3 PO 状态流转

PO 有三种状态：

| 状态 | 英文标识 | 说明 |
|------|----------|------|
| 草稿 | draft | 初始状态（当 SC 为草稿时），可编辑、可删除 |
| 激活中 | activing | PO 已激活，可创建 GR、可执行收货 |
| 已完成 | finished | PO 业务完结 |

**状态流转规则**:

| 操作 | 从 | 到 | 谁可以操作 |
|------|----|----|------------|
| 提交 | 草稿 | 激活中 | SC 所有人 / 管理员 |
| 完成 | 激活中 | 已完成 | SC 所有人 / 管理员 |
| 撤销 | 激活中 | 草稿 | SC 所有人 / 管理员 |
| 撤销 | 已完成 | 激活中 | SC 所有人 / 管理员 |
| 删除 | 草稿 | （删除） | SC 所有人 / 管理员 |
| 删除 | 激活中 | （删除） | SC 所有人 / 管理员 |
| 删除 | 已完成 | （删除） | SC 所有人 / 管理员（级联删除关联 GR 和附件） |

**关键说明**:
- PO 提交时会进行预算检查：该 SC 下所有 PO 金额之和不得超过 SC 总金额
- PO 在激活中 (activing) 状态下即可创建 GR，不必等到完成
- SC 关闭后，其下所有 PO 不可再做任何变更

### 4.4 PO 详情页

PO 详情页展示：

- **PO 基本信息**: 编号、金额、供应商、状态等
- **所属 SC 信息**: 关联的 SC 编号和名称
- **预算状况**: PO 金额、已核销金额、可用余额
- **关联 GR 列表**: 该 PO 下所有的 GR

### 4.5 PO 附件管理

与 SC 附件管理类似，您可以为 PO 上传、查看和删除附件。操作方式请参考 [3.11 SC 附件管理](#311-sc-附件管理)。

## 5. GR 管理

GR（Goods Receipt）代表收货确认，从 PO 中核销预算，是整个资金链路的终点。

### 5.1 GR 列表页

点击侧边栏 **GR** 进入列表页，展示所有 GR 的整体视图。列表包含以下关键列：

| 列名 | 说明 |
|------|------|
| GR 编号 | 系统自动生成的唯一编号 |
| 所属 PO | 该 GR 对应的 PO 编号 |
| 所属 SC | 该 GR 对应的 SC 编号（通过 PO 关联） |
| 预估金额 | 预计收货金额 |
| 合同金额 | 审批通过后的实际金额 |
| 状态 | 当前状态（草稿/经理确认中/待审批/已通过/已取消） |
| 创建日期 | 创建日期 |

### 5.2 创建 GR

1. **方式一**: 在 PO 详情页，点击 **新建 GR** 按钮
2. **方式二**: 在 GR 列表页，点击 **新建 GR** 按钮，然后选择目标 PO
3. 填写 GR 信息：
   - **预估金额 (estimated_amount)**: 预计的收货金额，创建时填入，用于占用预算
   - **税率 (tax_rate)**: 可选，用于计算含税合同金额
   - **其他字段**: 货物/服务描述、收货期间等
4. 点击 **保存** 创建 GR

> **GR 初始状态**:
> - 若 PO 为草稿 → GR 创建为 **草稿**
> - 若 PO 为激活中 (activing) 且 SC 已通过 → GR 创建为 **待审批 (pending)**（亦可选择草稿）

### 5.3 GR 状态流转

GR 有五种状态：

| 状态 | 英文标识 | 说明 |
|------|----------|------|
| 草稿 | draft | 初始状态（当所属 PO 为草稿时） |
| 经理确认中 | manager_confirm | 提交后等待管理员确认 |
| 待审批 | pending | 管理员确认后，等待审批 |
| 已通过 | approved | 审批通过，合同金额生效，预算正式核销 |
| 已取消 | cancelled | 已取消，预算释放 |

### 5.4 提交 GR

将草稿 GR 提交，进入管理员审核流程：

1. 在 GR 详情页点击 **提交** 按钮
2. 系统校验：
   - 所属 PO 必须为 **激活中 (activing)** 状态
   - 预估金额不超过 SC 和 PO 的可用余额
3. GR 状态从 **草稿** 变更为 **经理确认中**

### 5.5 管理员确认 GR

GR 提交后，需管理员确认才能进入审批：

1. 管理员进入处于"经理确认中"的 GR 详情页
2. 点击 **确认** 按钮
3. GR 状态变更为 **待审批**

### 5.6 GR 审批与取消

**审批通过**:
1. 管理员进入待审批 GR 的详情页
2. 点击 **通过** 按钮
3. 系统计算合同金额（含税）：`con_value = estimated_amount × (1 + tax_rate/100)`，也可手动指定
4. GR 状态变更为 **已通过**，合同金额正式生效并核销 SC/PO 预算

**取消**:
1. 管理员在待审批 GR 的详情页点击 **取消**
2. GR 状态变更为 **已取消**，占用的预估金额被释放

### 5.7 撤销 GR（回退操作）

GR 支持回退操作：

| 当前状态 | 撤销后状态 | 谁可以操作 |
|----------|------------|------------|
| 待审批 | 经理确认中 | SC 所有人 / 管理员 |
| 已通过 | 待审批 | SC 所有人 / 管理员 |
| 已取消 | 待审批 | SC 所有人 / 管理员 |

### 5.8 删除 GR

可删除草稿、经理确认中、待审批、已取消状态的 GR（已通过的 GR 不可删除，需先撤销到待审批）。删除操作会同时清除关联的附件记录和文件。

### 5.9 GR 详情页

GR 详情页展示该条收货记录的完整信息，包括关联的 PO 和 SC，以及预算占用明细。

## 6. 供应商管理

供应商模块管理所有供应商信息，供 SC 和 PO 关联使用。

### 6.1 供应商列表页

点击侧边栏 **供应商** 进入列表页。列表包含供应商名称、状态（启用/停用）、联系方式等字段。

### 6.3 编辑供应商信息

1. 在供应商列表中点击要编辑的供应商
2. 修改信息后点击 **保存**

### 6.4 停用 / 启用供应商

- **启用**: 对已停用的供应商点击 **启用**，恢复其可用状态

### 6.5 批量导入供应商

4. 导入完成后显示导入结果（成功/失败数量）

## 7. 邮件通知

POMP 支持自动发送邮件通知，包括状态变更通知和预算阈值提醒。邮件通过部门共享邮箱的 Outlook 自动发送。

### 7.1 通知系统概述

邮件通知的工作机制如下：

```
用户在 POMP 中操作（提交 SC、通过 PO 等）
        ↓
系统自动在数据库中写入通知队列条目
        ↓
专用机器上的通知脚本定期检查队列
        ↓
通过 Outlook 发送邮件
```

- **无需手动发送邮件**：所有邮件均由后台自动处理
- **通知类型**: 状态变更通知（SC 提交/确认/通过/驳回、PO 状态变更、GR 审批等）、预算阈值提醒（金额/时间）

### 7.2 通知配置

通知配置分为两个层级：

**全局默认设置**（仅管理员可配置）:
1. 点击侧边栏 **系统 → 通知默认设置**
2. 可配置：
   - **管理员收件人**: 接收所有通知的管理员列表
   - **状态变更规则**: 各类状态变更时是否发送邮件、收件人/抄送人
   - **阈值提醒规则**: 预算金额阈值（如剩余 50%/30%/10%）和时间阈值（如合同到期前 6/3/1 个月）

**按 SC 单独设置**（管理员和 SC 申请人均可配置）:
1. 进入 SC 详情页，找到 **通知设置** 区域
2. 可覆盖全局默认设置，针对单个 SC 定制通知策略

### 7.3 查看通知日志

点击侧边栏 **邮件** 进入通知日志页面，可查看：

- **通知队列**: 所有待发送、已发送、发送失败的通知记录
- **筛选条件**: 按状态（待发送/已发送/失败）、类型（状态变更/阈值提醒）、事件分类进行筛选
- **发送详情**: 每封邮件的收件人、主题、发送时间、状态

## 附录 A: 状态流转图

### SC 状态流转

```
  录入
   ↓
  草稿 (draft) ←────────────────────────────┐
   ↓                                         │
  经理确认中 (manager_confirm) ──→ 草稿 (撤销) │
   ↓                                         │
  待审批 (pending) ←── 经理确认中 (撤销)       │
  ↙       ↘                                  │
已通过    已驳回 ←── 草稿 (修改后重新提交)      │
(approved) (denied)                          │
  ↓       ↓                                  │
  ↓   重新提交 → 经理确认中                    │
  ↓                                          │
已关闭 (closed) ←── 已通过 (撤销) ─────────────┘
 (所有PO须finished, 所有GR须approved/cancelled)
```

> 其中"提交"操作接受 草稿 和 已驳回 两种来源

### PO 状态流转

```
  (SC为草稿时)          (SC为已通过时)
      ↓                      ↓
   草稿 (draft) ──→ 激活中 (activing) ──→ 已完成 (finished)
      ↑                 ↑      ↑               │
      │                 │      │               │
      └─── 撤销 ────────┘      └─── 撤销 ──────┘
```

| 操作 | 方向 | 说明 |
|------|------|------|
| 提交 | draft → activing | 手动提交，含预算校验 |
| 级联提交 | draft → activing | SC 审批通过时系统自动提交草稿 PO |
| 完成 | activing → finished | PO 业务完结 |
| 撤销 | activing → draft | 回退到草稿 |
| 撤销 | finished → activing | 回退到激活中 |

> PO 在 activing 状态下即可创建 GR，不必等到 finished。

### GR 状态流转

```
  录入
   ↓
  草稿 (draft)
   ↓
  经理确认中 (manager_confirm)
   ↓
  待审批 (pending)
  ↙       ↘
已通过    已取消
(approved) (cancelled)
```

**回退路径**:

| 当前状态 | 撤销后状态 |
|----------|------------|
| pending | manager_confirm |
| approved | pending |
| cancelled | pending |

> 已通过的 GR 不可直接删除，需先撤销到待审批状态。

## 附录 B: 预算计算说明

系统采用实时计算方式，所有预算数字均从 GR（收货记录）推导得出，确保数据一致性和精度。

### 计算公式

**SC 可用余额** = SC 总金额 - ∑ 待审批 GR 预估金额 - ∑ 已通过 GR 合同金额

**PO 可用余额** = PO 金额 - ∑ 待审批 GR 预估金额 - ∑ 已通过 GR 合同金额

### 计算逻辑说明

- 待审批 (pending) 状态的 GR，其 **预估金额 (estimated_amount)** 占用预算
- 已通过 (approved) 状态的 GR，其 **合同金额 (con_value)** 占用预算
  - 合同金额 = 预估金额 × (1 + 税率/100)，或由管理员手动指定
- 草稿 (draft)、经理确认中 (manager_confirm)、已取消 (cancelled) 状态的 GR 不占用预算

### 示例

假设：
- SC-001 总金额 = 100,000 元
- 关联 PO-001，金额 = 60,000 元
- PO-001 下 GR-001（已通过），合同金额 = 20,000 元
- PO-001 下 GR-002（待审批），预估金额 = 10,000 元

则：
- PO-001 可用余额 = 60,000 - 10,000 - 20,000 = **30,000 元**
- SC-001 可用余额 = 100,000 - 10,000 - 20,000 = **70,000 元**

## 附录 C: 常见问题

**Q: 为什么我看不到某个 SC？**

A: 请确认以下可能原因：
- 该 SC 处于草稿状态且您不是创建者（草稿仅对创建者可见）
- 您没有该 SC 的查看权限（请联系管理员确认）

**Q: 创建 PO 时提示"超出 SC 可用余额"怎么办？**

A: PO 金额不能超过所关联 SC 的当前可用余额。您可以：
- 减小 PO 的订单金额
- 检查该 SC 下是否已有其他 PO 和 GR 占用了预算

**Q: 供应商停用后，历史数据会受影响吗？**

A: 不会。已停用的供应商仅是在新建 PO 时不再出现在候选列表中，历史 PO 数据不受影响。

**Q: 如何修改已提交的 SC？**

A: SC 提交后即进入不可编辑状态。您可以通过**撤销**操作将 SC 回退：
- 经理确认中 → 撤销到草稿，修改后重新提交
- 待审批 → 撤销到经理确认中，再由管理员确认为待审批
- 已通过 → 仅管理员可撤销到待审批（需管理员处理）

如果 SC 被驳回，您可以直接修改后重新提交（驳回状态等同于可重新提交的草稿）。

**Q: GR 的"预估金额"和"合同金额"有什么区别？**

A: 预估金额是提交 GR 时的预计收货金额，用于预先占用预算；合同金额是审批通过时的实际金额（含税）。两者都会影响预算计算：
- 待审批 GR 使用预估金额占用预算
- 审批通过后，预估金额的占用被合同金额替代（合同金额可能因税率而高于预估金额）

**Q: PO 在 activing 状态能创建 GR 吗？需要等到 finished 吗？**

A: PO 在激活中 (activing) 状态即可创建 GR，这是设计的正常流程。finished 是 PO 全部收货完成后的终态，不需要等到 finished 才开始收货。

**Q: 文件锁是怎么回事？**

A: 当有人在编辑某个 SC（或其下的 PO/GR）时，系统会自动锁定以防止多人同时修改造成数据冲突。如果提示锁定失败，请稍等片刻再试。

**Q: 哪些角色可以执行"经理确认"操作？**

A: 只有管理员 (Admin) 可以执行经理确认（confirm）。SC 和 GR 提交后进入"经理确认中"状态，需管理员确认后才能进入待审批队列。

## 附录 D: 编号规则说明

POMP 中的所有业务编号（SC、PO、GR）均由系统自动生成，无需手动输入。

**编号格式**: `{类型}-{用户ID}-{日期}-{序号}`

例如: `SC-V2SE7PP-20260611-001`

| 组成 | 说明 | 示例 |
|------|------|------|
| 类型 | SC / PO / GR | SC |
| 用户 ID | 创建者的 Windows 账号 | V2SE7PP |
| 日期 | 创建日期 (YYYYMMDD) | 20260611 |
| 序号 | 当天的流水号 (3 位，从 001 开始) | 001 |

这种编号方式保证了多个用户在同一天各自创建记录时不会产生编号冲突。
